# Отчёт в Excel

Главное ограничение проекта: отчёт — это **чужой файл**. Руководитель присылает Excel-шаблон на месяц, и компания принимает только его — под тем же именем, с той же структурой и оформлением. Приложение должно только вписать значения.

## Почему не exceljs / openpyxl

Библиотеки вида «открыть книгу → изменить → сохранить» пересобирают весь пакет xlsx. На реальном шаблоне это привело к потерям: выпали внешние ссылки на другие книги, перенумеровались стили, остались сотни битых именованных диапазонов — и Excel при открытии предлагал «восстановить» файл. Для отчёта, который проверяет компания, это неприемлемо.

## Как пишем: хирургическая правка XML

xlsx — это zip-архив с XML-файлами. Отчёт собирается так (`backend/src/report/xlsx-template.ts`):

1. Открываем исходный файл как zip (**JSZip**), находим лист визитов — первый лист, где в колонке D есть даты.
2. Разбираем только XML этого листа: строки, ячейки, объединения.
3. Вписываем значения как `t="inlineStr"` **в существующие пустые ячейки**, сохраняя их атрибут стиля `s` — оформление ячейки не меняется. Общая таблица строк (`sharedStrings.xml`) не трогается.
4. Собираем XML листа обратно: меняются только тронутые строки, всё остальное — исходный текст файла.
5. Все прочие части архива (стили, другие листы, внешние ссылки, имена) копируются **как есть**.

Результат: на реальном шаблоне из 46 частей архива меняется одна (лист), внутри неё — только заполненные ячейки. Excel открывает файл без предупреждений; проверено автоматизацией Excel, которая падает с ошибкой на повреждённом файле.

Имя файла при выгрузке — исходное (`Content-Disposition` с `filename*=UTF-8''…`); на телефоне файл пишется во временную папку ровно под этим именем, поэтому в WhatsApp он уходит без «(1)» и переименований.

## Устройство шаблона

```
 A (день недели,        B   C        D (дата)     E (ЛПУ/аптека)        F (адрес)       G…N (визит)
 объединена на блок)
┌──────────┬────┬────────┬────────────┬──────────────────────┬──────────────┬──────────────
│          │ 1  │ Врач   │ 22.10.2026 │ Городская пол-ка №3  │ ул. Лесная 12│
│          │ 2  │ Врач   │            │                      │              │  ← «там же»
│ четверг  │ 3  │ Врач   │            │                      │              │
│          │ 4  │ Аптека │            │ Аптека Фармленд      │ ул. Садовая 46│
│          │ …  │        │            │                      │              │
│          │ 22 │ Врач   │            │                      │              │  ← запасные
└──────────┴────┴────────┴────────────┴──────────────────────┴──────────────┴── жирная граница
```

- Месяц — готовая сетка: на каждый рабочий день блок строк, колонка A объединена на весь блок, дата в D первой строки.
- **Шаблон — это план.** На каждый день руководитель заранее вписывает ЛПУ и адрес в строку-заголовок; строки под ней с пустым E означают «там же» (обойти N врачей в этом ЛПУ). Аптеки обычно — каждая своей строкой.
- Колонке C («Врач» / «Аптека») верить нельзя — её заполняют как попало; тип места определяется по справочнику, сети и словам в названии (`report/place-kind.ts`).

### Колонки строки визита

| Колонка | Что | Как заполняем |
|---|---|---|
| C | Врач / Аптека | только если пусто (в занятой строке плана — по факту) |
| E | ЛПУ / аптека | только в строку, которая открывает группу |
| F | Адрес | так же; в заголовок плана без адреса — дописываем |
| G | ФИО | |
| H | Специальность | |
| I | Телефон | строкой |
| J–M | Препараты 1–4 | «Коф Йог»; аптека — «Коф Йог 9» или «Коф Йог: ост. 5, прод. 3, заказ 10»; больше четырёх — через запятую в M |
| N | Комментарий | «посмотрит» + «Договорённость: …; факт: …; отклонение: …» |

## Раскладка визитов по строкам (`placeDay`)

Задача: разложить визиты дня так, как это сделал бы человек, заполняющий план вручную.

1. **Визиты по плану** — в первую свободную строку группы своего места. ЛПУ и адрес в строки под заголовком не пишем («там же»).
2. **Остальные** (места нет в плане или его группа заполнена) — в порядке ввода открывают новую группу в свободном хвосте последней группы дня (запасные строки в конце дня): пишем E и F, следующие визиты туда же ложатся под неё. Так запланированные места не теряют свои строки, пока медпред ещё в пути.
3. **Запасные строки кончились** — визит занимает группу плана, где не заполнено ни одной строки (туда в этот день не ходили): ЛПУ и адрес плана заменяются фактическими. Так делают и вручную. На экране «По плану» этого не происходит — запланированное место не пропадает из списка посреди дня.
4. **Не хватило и этого** — добавляем строки (ниже).

### Одно место = название + адрес

У сетей аптек одно название на десятки адресов, поэтому сравнивается пара «название + адрес» (`common/place-match.ts`):

- регистр, «ё/е», кавычки, «№», точки и лишние пробелы не важны;
- пустой адрес подходит к любому;
- адреса — одно место, если совпадает улица **с допуском на опечатку** (расстояние Левенштейна 1–2 буквы в зависимости от длины слова) и номера домов не противоречат.

| Адреса | Результат |
|---|---|
| «Садовая 46» и «ул. Садовая, 46» | одно место |
| «Цвиточная 32» и «Лесная Цветочная» | одно место (опечатка, угол улиц) |
| «Лесная 1» и «Лесная 10» | разные — номера домов разные |
| «Лесная 10» и «Садовая 46» | разные — другая улица |

Та же функция используется в справочнике (филиалы сети не сливаются в одну запись) и в форме визита (подсказки «Аптека Фармленд · ул. Садовая 46», договорённость аптеки переносится по названию и адресу).

### Визитов больше, чем строк: вставка строк

Если строк дня не хватает, отчёт **добавляет строки** — так же, как человек вставляет строку в Excel:

- строки вставляются **перед последней строкой дня** (у неё жирная нижняя граница — граница дня остаётся внизу);
- оформление берётся у самой частой строки середины дня, номера в B нет;
- всё ниже сдвигается: номера строк и ссылки ячеек, объединения (ячейка дня недели растягивается на новые строки), `dimension`, автофильтр, выделение, разрывы страниц, именованные диапазоны книги, указывающие на этот лист;
- если на листе есть формулы, рисунки, таблицы или на лист ссылаются другие части книги — строки не добавляются (сдвинуть их безопасно нельзя), визиты уходят в предупреждение.

Сколько строк добавить, определяется итеративно: раскладка → сколько не влезло → добавить → разложить заново.

## Предпросмотр

`GET /reports/preview?date=` отдаёт строки дня ровно такими, какими они будут в файле: номер строки, № слота, «Врач/Аптека», значения E–N, откуда строка (из файла / из приложения / пусто), добавлена ли она. Отчёт и предпросмотр используют одну функцию планирования (`planFill`), поэтому не могут разойтись.

## Импорт уже заполненного месяца

При загрузке шаблона заполненные строки (не пусты G–N) превращаются в визиты «из файла»:

- строки с пустым E получают место и адрес от заголовка своей группы;
- препараты распознаются нечётко (`row-import.ts`): опечатки (расстояние Левенштейна), латинские буквы-двойники («Кoф» с латинской o), слитное написание, остатки после названия («Коф йог 7 и Вормзвин 10»); исходный текст сохраняется;
- справочник пополняется в режиме «только дописать недостающее»;
- при повторной загрузке файла визиты «из файла» читаются заново, визиты из приложения не удаляются, а сопоставляются со строками по дате и ФИО — уже выгруженный отчёт не задваивается.

### Правка визитов «из файла»

Визит «из файла» можно исправить или удалить в приложении (кроме переноса на другой день — его строка в блоке своего дня). Такой визит помечается `fileEditedAt`, и экспорт перезаписывает его строку (`applyFileEdits` в `xlsx-template.ts`; общая часть отчёта и предпросмотра):

- колонки визита G–N пишутся заново; J–M — только если препараты исправили, иначе остаётся исходный текст файла (там бывает то, что не распознали);
- удалённый визит очищает G–N; план строки (E/F) остаётся;
- визит в другом ЛПУ — ЛПУ и адрес пишутся в его строку, а следующей занятой строке «там же» возвращается прежнее ЛПУ, чтобы она не «переехала»;
- повторная загрузка того же шаблона правку не затирает: строка на месте (тот же номер и день) — исправленный визит остаётся к ней привязан; строки нет — становится обычным визитом приложения.

## База врачей и аптек

Второй файл руководителя — «База врачей и аптек» (экран «Ещё → База врачей и аптек», `src/base`). Загружается один раз и хранится нетронутым; при каждом скачивании в копию вписывается справочник медпреда. Примитивы правки XML общие с отчётом (`src/xlsx/xlsx-xml.ts`), остальная книга — скрытые листы, внешние ссылки, стили — не меняется.

- **Листы и колонки — по заголовкам**, а не по буквам: врачи — лист, где в строке шапки есть «ФИО» и «ЛПУ», аптеки — «ФИО» и «Аптека». Колонки: №, МП, Город, ФИО, Специальность, Телефон, ЛПУ/Аптека, Адрес, Препараты, Потенциал. Город — из шапки («Город Алматы») или из строки-примера; «Потенциал» — Низкий / Средний / Высокий, его отмечают в визите к врачу или в «Справочнике» (не отмечен — пусто).
- **Запись**: с первой строки под шапкой, подряд. Подготовленные строки сохраняют своё оформление (у руководителя оно разное по строкам), новые копируют оформление строки выше; нумерация № продолжается. Строка-пример руководителя заменяется и получает обычное оформление соседних подготовленных строк (у руководителя она красная), ниже записей значения в колонках базы стираются. Ячейки вне колонок базы (справочная табличка сбоку) не трогаются. Фильтр, условное форматирование (подсветка повторов ФИО) и размеры листа растягиваются на новые строки.
- **Только те, кто есть в визитах.** Справочник помнит всех, кого когда-либо вводили (опечатки, удалённые визиты, старое ФИО после исправления) — это нужно для подсказок. В базу идут только врачи и провизоры с живым (не удалённым) визитом из приложения или из файла; аптеки без провизора — только если в них был живой визит (место с визитом сверяется по названию и адресу).
- **Один человек — одна строка** (`base-rows.ts`). Справочник заводит врача по точному ФИО, поэтому повторы бывают: без отчества в одной записи («Иванова Анна» и «Иванова Анна Сергеевна» — тот же, если совпадает ЛПУ или специальность, иначе это могут быть тёзки) и опечатка в отчестве (до 2 букв). Записи сводятся: полное ФИО, свежие телефон и место, недостающее — из старых; препараты — из всех визитов, чаще показанные первыми.
- **Правка в «Справочнике»** (Ещё → Справочник, `directory-edit.service.ts`): ФИО, специальность, телефон, ЛПУ, адрес, потенциал, «не включать в базу» (строка пропадает из файла, в подсказках врач остаётся). С галочкой «исправить и в визитах этого месяца» сервер меняет те же значения в визитах месяца — только поля, где было старое значение; пустое в визите не заполняет (врач мог не дать телефон на этом визите).
- Провизор — тот же, если то же имя в той же аптеке; аптеки без провизоров идут строкой без ФИО. Врачи сортируются по ЛПУ и ФИО, аптеки — по названию и адресу.
- Шаблон отчёта как базу загрузить нельзя (в нём тоже есть «ФИО» и «ЛПУ») — сервер отвечает, что это шаблон отчёта. И наоборот: файл базы, присланный через «Поделиться», сначала пробуется как шаблон отчёта, а не подошёл — загружается как база.
